# Правила работы с репозиторием

## Git
- Коммиты и пуш — всегда прямо в ветку `main`, без отдельных веток и pull request'ов.
- Перед пушем: `git fetch origin main` и проверить, что история линейная (fast-forward).
- Автор коммитов — `KhArtN <KhArtNJava@gmail.com>`; сообщения коммитов — на русском.

## Проект
- Конвертер DOCX, ODT, RTF, HTML и MHTML → PDF на C# (.NET 10), только стандартная библиотека, без сторонних пакетов.
- Сборка: `dotnet build -c Release`; программа — `src/DocxToPdf/bin/Release/net10.0/docx2pdf`.
- Общение, комментарии в коде, README — на русском.
- Новые возможности описывать в `README.md` (разделы «поддерживается», таблица «Устройство», «Ограничения»),
  тестовые файлы класть в `tests/<формат>` с описанием в README каталога.
- Картинки сравнения с эталоном — в `docs/compare`, не в корне.
- Библиотека — `src/DocxToPdf.Library` (те же исходники, `DocxToPdf.dll`); руководство — `docs/library.md`.
  Релиз: `tools/release/release.sh <версия>` → архивы `DocxToPdf-<версия>-lib.zip` и `-docs.zip`, тег `v<версия>`.
  Публикует релиз workflow `.github/workflows/release.yml` (из облачной сессии создавать релизы и теги нельзя).
- Перед коммитом: сборка без предупреждений, сравнение вывода с прежней сборкой (регрессия),
  сверка с эталоном (Chromium для HTML, LibreOffice для DOCX/ODT/RTF).
